# Toolkit improvement candidate

**Content class:** Candidate — not released instruction or policy.

## Observed signal

Type: `failure` or `recurring_workflow`.

Describe the behavior or theme, decision impact, and sanitized project evidence. Do not store raw sensitive logs, transcripts, or hidden reasoning traces.

## Evidence

Reference the smallest useful set of learning signals and relevant run metadata.

## Why this merits a toolkit change

Explain why the signal is reusable and material rather than one-off friction or repeated wording.

## Responsible layer

Choose the narrowest owner: project-local instruction/reference, `PROJECT_MAP.md`, `project.yaml`, skill reference, `SKILL.md`, shared instructions, adapter, capability policy, tooling/onboarding, or a genuinely distinct new skill. Do not promote one-off project peculiarities globally.

## Proposed narrow change

Name the maintained or protected file that would change and state the behavioral delta. For protected policy, propose only; never apply automatically.

## Reproducing evaluation

Reference the synthetic case or describe the sanitized fixture, observable invariant, forbidden behavior, and expected artifact/verdict needed to reproduce the signal.

## Regression scope

List existing cases that must still pass and explain why the proposal does not broaden permissions, duplicate instructions, or add speculative machinery.

## Review and release record

Record human reviewer, validation commands/results, release decision, and released version only after the maintenance workflow completes. Until then this document remains non-loading candidate content.
